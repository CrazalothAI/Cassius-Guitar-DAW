# Take library and offline reamping

In standalone, open **Takes**. Finished guitar recordings enter automatically after both WAV headers are finalized. Use **Import take folder** for an earlier Cassian folder containing matching mono `Guitar dry.wav` and stereo `Guitar processed.wav` files. New recordings save `Original rig.json` and an incomplete `Cassian take.json` before arming; finalization atomically replaces the metadata. The rig snapshot represents the starting settings; parameter changes during recording are not recorded as automation.

Since 1.3.0, the disk worker updates and flushes the three WAV headers at approximately two-second intervals while audio has been written. This makes a readable checkpoint prefix available without waiting for finalization. Disk/seek/flush failures stop recording as incomplete. This reduces recovery exposure; it does not guarantee data survival through power loss or recover raw tails beyond a readable header.

## Recover an interrupted recording (1.3.0)

Open **Recover interrupted recording**, then **Choose interrupted take folder**. Stop recording, exports and backups first. Recovery validates uncompressed RIFF WAV headers and physical data bounds, requires mono dry/stereo processed stems at the same sample rate, and copies their common readable prefix into `Cassian/Library/RecoveredRecordings/<unique-folder>`. Original files are never overwritten. A usable stereo backing stem is trimmed to the same length; missing, short or unreadable backing is omitted with an explanation. A reasonably sized original rig snapshot is preserved.

The local **Recording recovery report.json** records the source, actual frames/rate, backing decision and limits. **Open recovered files** locates it. The new take is initially incomplete: select it, listen to **Original processed**, check the review acknowledgement and choose **Confirm recovered take**. Confirmation rechecks dry/processed and any included backing against their recovery checksums before enabling WAV exports, reamping and recorded-rig loading. It stores approval in the take catalog, not in the interrupted original. Approval survives reopening and unchanged reimports; changed audio clears it on reimport.

Since 1.4.0, standard mono/stereo WAV takes beyond the 256 MiB decoded limit can be reviewed directly through bounded streaming. An external-player acknowledgement remains available when a file or device rate is unsupported: open the folder, listen to `Guitar processed.wav`, then explicitly acknowledge **Review in another player** and confirm. The same byte/range checks apply. The checkbox is a human review acknowledgement, not an automatic sound-quality assessment.

Recovery is explicit, cancellable and serialized on the take worker. A per-folder lock rejects active recordings made by this version. Source checksums are compared before/after copying to detect changes from other writers. Cancelled/failed copies are cleaned from their private staging folders; a failed catalog registration rolls back memory and removes only the new copy. The catalog remains an atomic single-file write, not a multi-file power-failure transaction. Recovery has an approximately 2 GiB processed-output limit and needs room for separate stems; it does not repair damaged headers, support RF64 input, find arbitrary recordings automatically, resume a take, or reconstruct session automation. Older recordings are recoverable only if they have readable headers.

Search names and creation dates, filter Favorites, select a take, edit its name and favorite flag, then press Save. Names do not rename files. The catalog lives at `takes.xml` under the existing shared library directory. It references recording folders rather than copying audio. Keep those folders available; a moved folder must be imported at its new location. Names and favorites persist across app launches. Independent catalog writes preserve other take entries; simultaneous edits to the same entry use the last saved entry.

0.5.0 adds **Newest first**, **Name** and **Favorites first** sorting. Sorting and filtering leave the selected take/version unchanged. Select a reamp version to edit its label with **Rename version**; this changes the catalog only, never the WAV/snapshot filename or contents. Labels permit 1–80 characters and persist across reopening. Failed catalog writes roll back the label and report a worker error. Original processed and Dry DI keep their fixed labels.

**Export guitar WAV** is a shortcut for the entire selected version: guitar only, neutral export gains, 48 kHz / 24-bit stereo, 10 ms edge fades and existing −1 dBFS peak protection. It includes any reamp tail and ignores the soundtrack range/mix controls. Backing and metronome are excluded. Use **Video soundtrack** for custom trimming and backing mix instead.

## Review

Select Original processed, Dry DI or an exported reamp version, then press **Listen**. Review uses its own seek and volume controls, starting at −12 dB. It bypasses guitar processing, pauses backing playback and mutes live guitar and the metronome while playing. Master and the output limiter still protect monitoring. **Stop review** restores live monitoring; backing playback stays paused. Starting practice playback or recording stops pending/active reviews.

Review uses worker-side decoding and filtered resampling. Shorter takes retain the decoded path, limited to 256 MiB of stereo float audio at the interface rate. Longer standard RIFF WAV takes use sixteen immutable stereo blocks, a 2,097,280-byte cache plus bounded worker/resampler scratch space. This is a take-review feature; backing-track speed changes keep the existing decoded limit. Practice and short review can retain separate decoded buffers. DAW playback and recording remain owned by the host, so this panel's native transport is standalone-only.

Long-take review supports normal-speed Play/Pause/Stop, seeking, mono duplication, stereo playback, waveforms and saved A–B ranges. Since 1.5.0, section recall pauses at A and enables looping. Loop prefetch shares the existing sixteen-block cache between current playback and the loop start; readiness requires the start and following block. Fractional loop boundaries interpolate into the true A frame, and the existing optional cosine edge fades apply. Loops may end at EOF. Preparation is shown in Takes, and missing audio holds the cursor instead of skipping ahead. Speed changes remain unsupported for streamed take review. Whole sample rates from 8 to 384 kHz are supported; this does not add RF64 playback or extend recording's standard-WAV duration/size limits. Initial preparation scans the source for a bounded waveform and cancellable content hash before playback, so a large file can take longer to open.

**Playback buffer waits** count cache waits, including intentional uncached seeks. They are separate from guitar-processing overruns and driver dropouts. Help's copied support report includes these numeric review diagnostics, without take names, paths, notes or section names.

If the cache falls behind or a distant seek needs preparation, **Buffering** holds the cursor and keeps live guitar muted while the worker refills it. It produces silence rather than skipping or replaying unrelated cached audio. The displayed playback interruption counter belongs to review buffering, including uncached seeks; it is separate from guitar DSP dropouts. Normal file deletion/size/modification changes and reader failures stop playback with a reload instruction. Independent physical RIFF bounds reject truncated declared audio even when a decoder would zero-fill it. Same-size edits that preserve modification timestamps are not continuously rehashed during playback.

0.5.1 adds **Pause review / Resume review**, **Set review A here**, **Set review B here**, **Loop A–B** and **Go to A**. Listen to the selected version first, seek to the desired boundaries and set A/B. B must be at least 0.05 seconds after A. The loop uses 5 ms edge fades; overlapping fades are bounded to a quarter of the loop length. Pause keeps the current position and restores live monitoring; Resume continues from that position. Resuming at the natural end restarts the version.

The review status names the loaded take/version even when you select another row or version. Seeking, pause/resume and loop controls remain disabled until your selection matches the loaded audio. Press Listen to load that selection; it resets the loop to the full version. Stop invalidates the loaded identity and cancels decoding or queued previews. Missing audio reports an error and leaves the controls unavailable. Review controls are blocked during recording. Loop bounds are temporary listening controls: they do not trim recordings, change reamp rendering or alter Video soundtrack export ranges. Review volume remains global.

0.5.2 adds a waveform for the loaded review version. Click to seek or use arrows (one second), Shift+arrows (ten seconds), Home and End. The cursor and A/B region follow review playback. Only the matching loaded version can expose or control its waveform; selection changes hide the previous envelope. Waveform failures leave the normal position slider usable. The existing decoder prepares at most 512 min/max pairs on its worker; playback-position polling does not rescan audio.

## Reamp versions

Set up the desired amp, pedals, cabinets and effects, then choose **Reamp with current rig**. A separate processor prepares the snapshot's assets and streams the original dry file through the guitar chain on a worker. It does not change the live rig or depend on audio callbacks. The current Input gain and guitar processing are included; Master, output limiter, accompaniment and clicks are excluded.

Successful exports add uniquely named `Reamp <id>.wav` and `.json` files in the take folder and a version in the selector. The WAV is stereo 32-bit float with the original dry file's sample rate. Choose **Effect tail** before reamping: no extra tail, 1, 2 (default), 5 or 10 seconds. Extra frames feed silence through the same processor so delays and reverbs ring out; version duration and tail length persist in the catalog. It retains headroom above 0 dBFS, so use suitable playback gain. Original dry and processed files remain untouched. **Cancel export** discards an unfinished audio output. Preparation/read/write failures report an error instead of adding a successful version.

Reamping begins with fresh DSP histories. Model/effect latency remains and is not compensated. The selected tail has a fixed duration; effects with longer decay can still be cut at its end. Existing reamps without duration metadata keep their original duration in the editor. Each take permits up to 64 reamp versions; the catalog permits up to 2,048 takes. Standard WAV size limits apply. Incomplete recordings are marked and cannot be reamped from the panel. Recording must finish before starting review or an export.

Rig snapshots contain references to the selected assets, not a portable asset bundle. Assets must remain available for a future export or recall. Use Library relinking when a capture or cabinet has moved. This update does not add waveform editing, deletion, automatic catalog migration, or latency compensation.

## Recover a saved tone

Select Original processed or Dry DI and press **Load recorded rig** to restore the starting tone. Select a reamp version and press **Load reamp rig** to restore the tone used for that export. Save current edits first: recovery replaces the current tone, board, MIDI assignments and scenes. Input calibration, Master, metronome and Play Along settings stay as they are. Accepted recall stops review and pauses backing playback.

Snapshot reads run on the take worker; full document validation and prepared rig recall use the existing engine path. Missing assets reject before changing the current rig. Corrupt assets may fail during preparation, retaining the current tone and reporting the engine error. Recording, exports, incomplete takes and rig loading block recovery. Older takes without a snapshot can still be reviewed and reamped. Recovery does not change WAV files, snapshots or catalog entries. Recording-time knob changes are not reconstructed.

## Take notes

Open Take notes to save up to 2,000 characters of tuning, tempo, song and performance reminders. Search takes matches saved notes as well as names/dates. Notes live in the local take catalog, survive app restarts and are preserved by name/favorite edits and repeated folder imports. They do not enter rig snapshots or modify WAV files. Failed catalog writes restore the previous metadata and report an error. Writes also enforce the 8 MiB serialized UTF-8 catalog limit, including XML escaping, so adding notes cannot produce a catalog that the app cannot reopen.

## Saved review sections

After listening to a take version, set A and B, open Sections and save a name. Recall pauses at A and enables looping; Resume starts listening. Replace or delete a selected section using the same controls. Up to 32 sections per audio file and 48 characters per name are supported. Saves run on the take worker and preserve the range at the time of the request. Switching/stopping the review cancels queued requests for the previous version. Errors appear in Takes.

The standalone stores section JSON under the managed library `take-sections` directory, separately from backing-track sections, the take catalog and tone rigs. Sections follow exact WAV file contents: identical renamed copies share them; edited audio or different dry/processed/reamp files have different identities. Selecting a different version resets section selection. Existing catalogs and host states need no migration; there are no new automation parameters. Sections are local annotations and are not embedded in exported WAVs or rig packs.

## Export a reviewed phrase (0.6.0)

Recall a saved section or set A-B while reviewing the selected version. Under Video soundtrack, press Use review A–B to copy it into Start/End. Export range as guitar WAV saves that excerpt with neutral export gain and the chosen edge fade; Export for video includes the requested guitar/backing balance. Copying requires the selected version to be loaded and the range to fit its actual duration. Switching take/version resets export bounds; subsequent review loop edits do not silently change them. The completion report shows actual written duration and applied peak attenuation. See [video export](VIDEO-AUDIO-EXPORT.md).

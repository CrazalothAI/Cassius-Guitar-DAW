# Cassian 1.4.0 Preview — bounded long-take review

Standalone Takes can now play standard mono/stereo WAV versions that exceed the old 256 MiB decoded-memory limit. Shorter versions retain their existing decoder and review loops. The new path owns sixteen stereo blocks with a fixed 2,097,280-byte audio cache, plus bounded worker resampler/scratch space. Readers, waveform scanning, cancellable content hashing, resampling and destruction stay off the audio callback. This is review playback, not a change to recording, DI, reamping or WAV exports.

Long review supports Play/Pause/Stop, original-time seeking, mono duplication, stereo, exact endpoint stopping and saved sections/export ranges. The worker reads a requested source-frame range and publishes an immutable block. Ready slots are claimed before callback inspection; Reading slots cannot be evicted. A replacement load uses the existing hazard-protected track lifetime and generation check; failed/cancelled preparation retains the old version. Seeking always checks the actual frame range, so an old cached range cannot be mistaken for a new seek. The same file's valid cached audio can be reused safely.

Source/interface rates from 8 to 384 kHz must be whole sample rates. Filtered resampling follows the same JUCE decoder path. Independent seek/block preparation aligns to the exact rational rate period and warms the Butterworth filter before publishing audio. An overlap sample allows fractional interpolation at block seams without callback access to another block. Independent RIFF physical-bound checks refuse truncated declared audio; deletion/size/modification changes and decoder failures stop playback with an instruction to reload.

When an uncached seek or disk delay leaves audio unavailable, review produces silence and holds the cursor until it is ready. Live guitar remains muted during active review, including buffering. The UI shows Buffering and its own interruption count, including uncached seeks. The callback scans a missing range once per callback, not once per silent sample. These events do not increment guitar DSP dropout metrics.

This first increment plays long takes at normal speed. Long-review looping is explicitly disabled in the UI and native commands. A/B controls remain useful for saved/export ranges; recalling a section pauses at A without looping. Backing-track speed changes and their decoded-memory limit are unchanged. RF64, damaged-header repair, automatic session reconstruction and extension of recording's duration/size limits are separate work. Initial waveform/hash preparation still scans the source on the worker. Files are not continuously rehashed during playback, so same-size edits preserving modification timestamps are outside change detection.

## Validation

The UI suite passes 224 tests, including streaming/preparing/buffering/error states, loop availability, saved ranges and exact export selection. All four native suites pass (44.43 seconds), with independent ZIP64-fixture CRC verification. Native regression coverage compares streamed and decoded samples across 18 mono/stereo 44.1/48/96 kHz combinations, including distant fractional-phase seeks, block seams and EOF. A generated 12½-minute mono WAV expands past the old device-rate limit while retaining the same cache allocation. Tests cover pause/stop, replaced seeks, cancelled/replaced loads, shutdown cancellation, saved sections, live-guitar/click mute routing, withheld worker reads, resume, callback reader-thread assertions, concurrent cache eviction, failed reads, deleted files and truncated RIFF payloads. Existing recording/reamp/export/backup checks remain in the full native suite. The owner's local bank was exercised without including its files in public packages.

Standalone/VST3 builds, three level-10 pluginval runs, binary version checks and isolated installer/upgrade/uninstall tests pass. Installer checks preserve user data and use a separate smoke-test application identity. Browser visual inspection remains unavailable because the local browser-control runtime failed to initialize; automated component coverage is not a substitute for human visual acceptance.

Unsigned preview status remains explicit. Human sustained review, fresh-PC/actual-upgrade, real DAW/MIDI/camera acceptance, sound redistribution rights, signing and commercial records are still pending. Automated checks do not establish commercial readiness or superior sound. See [the playing checklist](PLAYING-CHECKLIST.md) and [the roadmap](PRODUCT-ROADMAP.md).
